Reviewed 2026-11-20. Recommendation: adapt the PR delivery and handoff workflows, reuse the existing PR policy and review skills, and keep multi-reviewer work opt-in.

## Decision (2026-11-20, supersedes the recommendations below)

The user chose to trust upstream over the agent-written PR policy, because the TStack author also wrote T3 Code and its PR tools.

- **Installed unedited** with `npx skills add -g t3dotgg/tstack` at `11e37a7`: `full-send`, `full-stop`, `council`, `babysit-pr`, plus their dependencies `sol-loop`, `file-pr`, `leaving-pr-comments`. They are tracked in `~/.agents/.skill-lock.json`, so `npx skills update` keeps them current. Keep local edits out of these skills.
- **Personal settings** live in `dot_agents/global-instructions.md` under "Pull requests", as the upstream README advises: council members by model family (Claude Opus `high`, GPT Sol `xhigh`, Gemini Neon `high` once available; two members make a full council), `council` replacing `sol-loop` when a full-send or full-stop request says "council", and GitHub login in agent comments. Council keeps upstream's unbounded rounds.
- **Removed:** `PR-WORKFLOW.md` (its CodeRabbit merge gate conflicts with upstream's advisory rule), the stale `ship-pr` skill, and Matt Pocock's `pr` skill (`npx skills remove -g pr`, so updates skip it; deselect it if `mattpocock/skills` is ever re-added wholesale).
- **Unchanged:** CodeRabbit configuration in each repo. `takeover` and `modernize` were not installed.
- **Remaining:** no live PR has run through these skills yet.

## Recommendation

Start with two small changes if you decide to adopt TStack. Add a single-owner handoff to the existing PR workflow. Then add two explicit delivery commands that share that workflow: **prepare for my merge** and **merge when ready**. The former is the safer general entry point. The latter is a good fit when you have explicitly asked the agent to finish unattended. Keep direct pushes, deployment, destructive cleanup, and thread settlement tied to what the user asked for. Your existing workflow already supplies the T3 watcher, current-head checks, and repository-specific review policy. [PR workflow](/home/lomzem/.local/share/chezmoi/dot_agents/PR-WORKFLOW.md:1)
