# Technical clarity adapted from ASD-STE100

ASD-STE100 Simplified Technical English is a controlled language for technical documentation. The full standard has a dictionary of approved words. Without it, use the most common word for each meaning, and use each word with one meaning only.

## Words

- Use one name for one thing. After you name a component, a file, or a state, use that exact name each time.
- Use technical names (component names, commands, error codes) as they appear in the system.
- Break hard-to-read noun clusters with a preposition: "the timeout of the cache server", not "cache server connection timeout value".
- Use the simple verb forms: the imperative, the infinitive, the simple present, the simple past, the future, and the past participle as an adjective.
- Use a verb to show an action. "Install the package" is correct. "Do the installation of the package" is not.
- Keep the articles ("a", "an", "the") and the other short words. Short words make the sentence structure clear.

## Sentences

- Write about one topic in each sentence.
- Use the active voice. Name the actor: "The scheduler starts the job."

## Procedures

- Write each instruction in the imperative: "Restart the server."
- Write one instruction in each sentence. Two actions that occur at the same time can be in one sentence.
- Put a condition before its instruction: "If the build fails, read the log."
- Use a numbered list for steps in a sequence.

## Descriptive text

- Put the most important information first.
- Write about one topic in each paragraph.
- Use a vertical list for a set of items, conditions, or results.

## Warnings and cautions

- Start a warning with a clear command: "Stop the service before you delete the volume."
- Then give the risk in a short sentence: "You cannot recover deleted data."
